Habitify — how to start (workflow only, no spoilers)
You already have a solid base: Vite + React + Tailwind + React Router, and you’ve already touched ThemeContext. Use the design as a map, not a checklist of finished code.

---
0. Run the app first

npm run dev
Keep the design open beside the browser. Every step should end with something you can see.

---
1. Break the UI into pieces (paper first)
Before coding features, name the blocks from the mock:
Area	What it is
Left	Sidebar (logo, nav, progress, dark mode)
Center	Header + overview cards + habit list
Right	Calendar + weekly ring + quote
Rule: one visual block ≈ one component later. Don’t build logic yet—just list names.

---
2. Build layout before logic
Order that works well for this screen:
App shell — 3 columns (sidebar | main | right)
Sidebar shell — empty boxes for nav / footer / toggle
Main shell — greeting, overview row, habits section
Right shell — calendar, week card, quote
Use static text and colors first. If layout looks wrong, fix layout before any state.

---
3. Theme early (you already started)
You have ThemeContext.jsx open — good place to begin:
Light / dark toggle in the sidebar
Apply theme on the root layout
Recheck that cards, text, and borders still look clean in both modes
Theme should wrap the app so every page can use it later.

---
4. Routing (pages from the sidebar)
Sidebar items = routes (even if most pages are placeholders at first):
Dashboard (this screen)
Habits
Statistics
Calendar
Insights
Settings
Wire nav highlight to the current route. Only fill out Dashboard fully at the start.

---
5. Static → interactive (one layer at a time)
For Dashboard, grow like this:
Hardcoded habits (names, colors, completed or not)
Toggle complete on click
Overview numbers derived from that list (don’t hand-type forever)
Add habit (simple form/modal)
Streaks / calendar dots after the list works
Don’t jump to calendar math before “check off a habit” works.

---
6. Where state should live
Think in this order:
Level	Use for
Local useState	Toggle, form open/close, one input
Context	Theme, maybe user name / shared habits
Later	localStorage so refresh doesn’t wipe data
Start local. Lift up only when two components need the same data.

---
7. Suggested build order (day-by-day style)
Shell + theme — 3-column layout + dark mode
Sidebar — nav + active link + progress bar UI
Overview cards — 4 stat cards (static numbers OK)
Habit list — rows with icon, name, streak text, check, menu
Habit interactions — complete / add / delete (minimal)
Right column — calendar month view, then week ring, then quote
Connect numbers — overview + week stats come from real habit data
Polish — spacing, hover, empty states, responsive (sidebar collapse if you want)
---
8. How to use the design without copying blindly
Match structure first (what sits where)
Match spacing and hierarchy second
Match exact colors/icons last
Build light mode first, then dark (or vice versa if theme is your focus)
---
9. Learning checkpoints (stop and test)
After each checkpoint, ask:
Does the layout still hold if I resize?
Does dark mode still look intentional?
Can I explain which component owns which piece of UI?
Is data flowing one way (parent → child), or am I tangled?
---
10. What not to do early
Don’t install a big UI kit before you understand the layout
Don’t build all 6 pages at once
Don’t over-engineer streaks/calendar until the habit list works
Don’t copy a full finished repo — the point is the path
---
One-line mantra
Layout → theme → routes → static content → local state → shared state → polish.
